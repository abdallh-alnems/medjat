## ١. نظرة عامة

نظام SaaS متكامل لإدارة الحضور والانصراف وحساب الرواتب، موجه للشركات الصغيرة والمتوسطة في السوق المصري والعربي. يجمع النظام بين إدارة الحضور بطرق متعددة، ملف الموظف الكامل، قواعد خصم مرنة، وحساب رواتب تلقائي — كل ذلك في منظومة واحدة متعددة الفروع.

### ١.١ المشكلة التي يحلها النظام

- غياب نظام متكامل يجمع الحضور + ملف الموظف + الرواتب في السوق المصري
- الأنظمة الموجودة إما معقدة جداً أو مكلفة أو غير مدعومة بالعربية
- الشركات الصغيرة تعتمد على Excel وورق مما يسبب أخطاء كثيرة
- لا يوجد حل مناسب للشركات متعددة الفروع بسعر معقول

### ١.٢ الميزة التنافسية

| الميزة | المنافسون | Medjat |
|--------|-----------|--------|
| ملف موظف كامل + أوراق | ❌ غير موجود | ✅ موجود |
| تحذيرات + تقييمات أداء | ❌ غير موجود | ✅ موجود |
| حساب راتب تلقائي | جزئي فقط | ✅ كامل |
| متعدد الفروع | ✅ موجود | ✅ موجود |
| عربي + سوق مصري | ❌ غير موجود | ✅ موجود |
| دفع محلي مصري | ❌ غير موجود | ✅ موجود |
| صلاحيات مخصصة مرنة | ❌ محدود | ✅ كامل |

│   موظف    │    إدارة    │  سوبر أدمن   │

                   ▼

| الوظيفة | التفاصيل |

### ٢.٤ الـ Multi-Tenant

```
شركة A  ←  tenant_id = 1
شركة B  ←  tenant_id = 2
شركة C  ←  tenant_id = 3

كل طلب للـ API بيحمل tenant_id
→ البيانات بتتفلتر تلقائياً
→ شركة A مش تشوف بيانات شركة B أبداً
```

## ٣. إنشاء الحسابات والمصادقة

النظام يدعم ٣ آليات منفصلة لإنشاء الحسابات وتسجيل الدخول — كل آلية مصممة لتناسب طبيعة المستخدم وحساسية البيانات اللي بيتعامل معاها.

### ٣.١ نظرة عامة على آليات الحسابات

| التطبيق | إنشاء الحساب | طريقة الدخول |
|---------|-------------|-------------|
| **تطبيق الإدارة (Owner)** | تسجيل ذاتي عند الاشتراك في باقة | Email + Password / Google / Apple |
| **تطبيق الإدارة (مديرين)** | دعوة من الـ Owner عبر Email | Email + Password / Google / Apple |
| **تطبيق الموظف** | إنشاء من تطبيق الإدارة + كود تفعيل لمرة واحدة | كود تفعيل مرة واحدة → Auto-login |
| **تطبيق السوبر أدمن** | يدوي من فريق التطوير | Email + Password + 2FA إجباري |

---

### ٣.٢ تسجيل الشركة الجديدة (Owner)

```
الشركة تختار إحدى الباقات
       ↓
صفحة Sign-Up:
  - اسم الشركة
  - اسم المالك (Owner)
  - Email
  - Password
  - رقم الموبايل
       ↓
Email Verification (رابط تفعيل)
       ↓
دفع الاشتراك عبر Paymob
       ↓
يُنشأ Tenant جديد + حساب Owner ✅
```

| العنصر | التفاصيل |
|--------|----------|
| التسجيل | ذاتي من صفحة Sign-Up |
| التحقق | Email Verification إجباري قبل الدفع |
| الدفع | عبر Paymob — يُفعَّل الحساب فور نجاح الدفع |
| النتيجة | يُولَّد `tenant_id` جديد ويُربط الـ Owner به |

### ٣.٣ دعوة المديرين (HR — Branch Manager — Attendance — Viewer)

المدراء **لا يسجّلون بأنفسهم** — يتم دعوتهم من قِبَل الـ Owner أو من له صلاحية "إضافة مديرين جدد".

```
الـ Owner من تطبيق الإدارة:
  - يدخل بيانات المدير الجديد (الاسم — Email — الدور — النطاق)
  - يحدد صلاحياته من قائمة الصلاحيات
       ↓
النظام يبعت Email للمدير الجديد:
  "تم دعوتك لإدارة شركة X — اضغط لتعيين كلمة المرور"
       ↓
المدير يضغط الرابط ويعيّن كلمة مروره
       ↓
يدخل تطبيق الإدارة بأي طريقة من طرق الدخول ✅
```

| العنصر | التفاصيل |
|--------|----------|
| مَن يدعو | Owner أو من له صلاحية "إضافة مديرين جدد" |
| رابط الدعوة | صالح ٧٢ ساعة، لمرة واحدة |
| إعادة الإرسال | متاح من تطبيق الإدارة لو الرابط انتهى |
| إلغاء الدعوة | متاح قبل تفعيل الحساب |

### ٣.٤ تفعيل حسابات الموظفين

الموظف **لا يسجّل بنفسه أبداً** — حسابه يتم إنشاؤه من تطبيق الإدارة، ويتم تفعيله بكود لمرة واحدة.

```
الشركة تضيف الموظف من تطبيق الإدارة
(الاسم — الوظيفة — الفرع — الراتب — رقم الموبايل — الأوراق — الصورة)
       ↓
النظام يولّد كود تفعيل عشوائي (مثال: 8K3M9P)
       ↓
الكود يظهر في تطبيق الإدارة للمدير
       ↓
المدير يبعت الكود للموظف (واتساب / يطبعه / شفهي)
       ↓
الموظف يفتح تطبيقه ويدخل: رقم الموبايل + الكود
       ↓
الـ Backend يتحقق ويُصدر Token دائم
       ↓
الكود يُحرَق (Burned) ولا يصلح للاستخدام تاني ❌
       ↓
في كل المرات التالية: التطبيق يفتح مباشرة بالـ Token المحفوظ
(Auto-login — بدون كلمة مرور)
```

#### مواصفات كود التفعيل

| العنصر | التفاصيل |
|--------|----------|
| الصيغة | ٦ خانات عشوائية (أرقام + حروف كابيتال) |
| الصلاحية | ٢٤ ساعة من وقت التوليد |
| الاستخدام | مرة واحدة فقط — يُحرق فور التفعيل |
| التكلفة | صفر — المدير يرسله يدوياً (لا يحتاج SMS Gateway) |
| إعادة التوليد | متاحة من تطبيق الإدارة لو انتهت الصلاحية أو فُقد الكود |

#### تغيير الجهاز

```
الموظف غيّر موبايله أو حذف التطبيق
       ↓
يطلب من المدير "كود تفعيل جديد"
       ↓
المدير يولّد كود جديد من تطبيق الإدارة
       ↓
الكود الجديد يُبطل الـ Token القديم تلقائياً
       ↓
يُسجَّل الحدث في سجل التحذيرات الخاص بالموظف
("تم تغيير الجهاز في تاريخ كذا" — للمراجعة)
```

#### حماية ضد Buddy Punching

> بما إن الـ Token الدائم محفوظ على **جهاز واحد فقط** في Secure Storage، أي محاولة دخول من جهاز تاني تُرفض تلقائياً — **حتى لو الموظف دفع بياناته لزميله**. ده بيحل مشكلة Buddy Punching من غير الحاجة لـ Face Recognition في الـ MVP.

### ٣.٥ طرق تسجيل الدخول

#### تطبيق الإدارة (Owner + المديرين)

| الطريقة | الاستخدام |
|---------|----------|
| **Email + Password** | الطريقة الأساسية — تعمل على أي جهاز |
| **Google Sign-In** | دخول بضغطة واحدة بحساب Gmail |
| **Apple Sign-In** | إجباري في تطبيق iOS لو فيه Google Sign-In (شرط App Store) |
| **Forgot Password** | استعادة عبر Email — فقط للحسابات اللي اتسجّلت بـ Email + Password |
| **مدة الـ Session** | ٣٠ يوم (Remember Me) — قابلة للتمديد |

##### قواعد ربط الحسابات

- لو المدير سجّل بـ Email + Password وبعدين دخل بـ Google **بنفس الإيميل** → النظام يربطهم لنفس الحساب تلقائياً (لا يُنشأ حساب جديد).
- لو الإيميل غير موجود في النظام → الدخول يُرفض مع رسالة: **"حسابك غير مفعّل، تواصل مع الشركة"**.
- لو الحساب اتعمل بـ Google/Apple فقط ومحاول يستخدم Forgot Password → رسالة: **"هذا الحساب مرتبط بـ Google/Apple، سجّل الدخول من هناك"**.

##### Apple Sign-In والإيميل المخفي

Apple بتسمح للمستخدم يخفي إيميله الحقيقي (`xxxx@privaterelay.appleid.com`). لتجنب مشاكل ربط الحسابات:
- المدير لما يضيف موظف أو مدير جديد، يستخدم **الإيميل الحقيقي** فقط.
- يُوضَّح في الـ UI: **"استخدم نفس الإيميل اللي ضافتك بيه الشركة"**.

#### تطبيق الموظف

| الطريقة | التفاصيل |
|---------|----------|
| **كود التفعيل** | مرة واحدة فقط في بداية الاستخدام (رقم موبايل + كود) |
| **Auto-login** | بعد التفعيل، التطبيق يفتح مباشرة بدون أي إدخال بيانات |
| **الأجهزة المسموحة** | جهاز واحد فقط (الـ Token محفوظ محلياً في Secure Storage) |
| **تغيير الجهاز** | يحتاج كود تفعيل جديد من المدير |
| **استعادة الوصول** | لا يوجد ذاتي — كل المسارات تمر عبر المدير |

#### تطبيق السوبر أدمن

| الطريقة | التفاصيل |
|---------|----------|
| **Email + Password** | إجباري — لا يوجد Google/Apple |
| **2FA** | إجباري (Google Authenticator أو ما يماثله) |
| **الوصول** | محدود بفريق التطوير فقط — لا تسجيل ذاتي |

### ٣.٦ الأمان الإضافي

| الميزة | الـ Owner | HR / Manager | Employee | Super Admin |
|--------|-----------|--------------|----------|-------------|
| **2FA** | اختياري (مُوصى به) | اختياري | غير متاح (Device Binding بديل) | **إجباري** |

## ٤. نظام الصلاحيات

النظام يعتمد على **صلاحيات مرنة قابلة للتخصيص**. الـ Owner يبني Role مخصص لكل شخص من قائمة صلاحيات محددة، مع تحديد النطاق (كل الفروع أو فرع معين).

### ٤.١ قائمة الصلاحيات المتاحة

| الصلاحية | الوصف |
|----------|-------|
| إدارة الموظفين | إضافة وتعديل وحذف الموظفين |
| تغيير قواعد الخصم | تعديل قواعد التأخير والغياب والإضافي |
| تسجيل الحضور | تحضير الموظفين يدوياً |
| مشاهدة التقارير | الوصول لتقارير الحضور والرواتب |
| إدارة الأوراق والملفات | رفع ومشاهدة وتعديل أوراق الموظفين |
| حساب الرواتب | مراجعة وإصدار كشوف الرواتب |
| إدارة الإجازات | الموافقة على الإجازات وتحويل الغياب |
| إضافة مديرين جدد | منح صلاحيات لمستخدمين جدد |
| تغيير إعدادات الشركة | تعديل بيانات الشركة والفروع |

### ٤.٢ الأدوار الافتراضية

| الدور | النطاق | الصلاحيات الافتراضية |
|-------|--------|----------------------|
| **Owner** | كل الفروع | كل الصلاحيات بدون قيود |
| **HR / مفوض** | كل الفروع | كل شيء ماعدا إضافة مديرين وإعدادات الشركة |
| **Branch Manager** | فرعه فقط | إدارة موظفين + حضور + أوراق + تقارير الفرع |
| **Attendance** | فرعه فقط | تسجيل الحضور فقط |
| **Viewer** | حسب التخصيص | مشاهدة التقارير فقط — لا تعديل |
| **Employee** | بياناته فقط | مشاهدة بياناته الشخصية فقط |

> **ملاحظة:** الأدوار قابلة للتعديل الكامل. مثال: مدير فرع المعادي يمكن منحه صلاحيات مدير لكن بدون تغيير القواعد، بينما مدير فرع رمسيس يمكنه تغيير قواعد فرعه فقط.

## ٥. نظام الحضور والانصراف

### ٥.١ الطرق الخمس لتسجيل الحضور

---

#### الطريقة ١: QR Code + GPS ✅ (الأساسية)

ورقة QR ثابتة معلقة في الفرع. الموظف يفتح التطبيق ويسكن الـ QR. في نفس اللحظة التطبيق يتأكد من الموقع الجغرافي للموظف.

```
الموظف يسكن QR الفرع
         +
GPS يتأكد إنه جوه النطاق
         ↓
لو الاتنين صح ✅ → يسجل الحضور
لو بعيد عن الفرع ❌ → يرفض
```

| العنصر | التفاصيل |
|--------|----------|
| آلية العمل | مسح QR + التحقق من GPS في نفس اللحظة |
| الحماية | لو الموظف خارج نطاق الفرع يُرفض حتى لو عنده الـ QR |
| الـ QR | ثابت لكل فرع — يمكن طباعته وتعليقه |
| نطاق GPS | يحدده الـ Owner بالمتر (مثال: 100 متر) |

---

#### الطريقة ٢: QR Code + GPS + Face Recognition ✅

نفس الطريقة الأولى مع إضافة التحقق من هوية الموظف عبر الكاميرا الأمامية.

```
الموظف يسكن QR
      +
GPS يتأكد من الموقع
      +
الكاميرا تفتح وتقارن وجهه
بصورته في ملفه (لا تحفظ صور جديدة)
      ↓
لو كل حاجة صح ✅ → يسجل الحضور
```

| العنصر | التفاصيل |
|--------|----------|
| التحقق | مقارنة الوجه بصورة الموظف المحفوظة — لا يحفظ صور جديدة |
| الحماية | يمنع Buddy Punching تماماً |
| التقنية | Google ML Kit — يعمل على الجهاز محلياً |

---

#### الطريقة ٣: تسجيل يدوي من المدير ✅

المدير أو من له صلاحية الحضور يسجل للموظف يدوياً من تطبيق الإدارة.

| العنصر | التفاصيل |
|--------|----------|
| الاستخدام | Fallback عند وجود مشكلة في التليفون أو الإنترنت |
| الصلاحية | Owner - HR - Manager - Attendance |
| التوثيق | يُسجل من قام بالتحضير اليدوي مع الوقت |

---

#### الطريقة ٤: Kiosk Mode ✅

تابلت أو موبايل ثابت عند باب الفرع. الموظفين يسجلون منه بدلاً من فتح التطبيق على هواتفهم.

| العنصر | التفاصيل |
|--------|----------|
| آلية العمل | الموظف يختار اسمه أو يسكن بطاقته أمام الكاميرا |
| الميزة | مناسب للموظفين الذين ليس لديهم smartphones |
| الأنسب لـ | المصانع والمطاعم الكبيرة |

#### الطريقة ٥: Offline Mode ✅

يعمل بدون إنترنت. البيانات تُحفظ على الجهاز وتتزامن تلقائياً عند عودة الاتصال.

| العنصر | التفاصيل |
|--------|----------|
| آلية العمل | QR + GPS بدون تحقق فوري — يُحفظ محلياً |
| التزامن | تلقائي عند عودة الإنترنت |
| الأهمية | ضروري للسوق المصري في المناطق ذات الإنترنت الضعيف |
| القيد | Face Recognition غير متاح في Offline Mode |

## ٦. نظام الخصم والإضافي

القواعد **غير ثابتة** — يحددها الـ Owner أو من له صلاحية تغيير القواعد. كل شركة لها قواعدها المستقلة تماماً.

### ٦.١ قواعد الخصم

| نوع الخصم | آلية التحديد | مثال |
|-----------|-------------|------|
| خصم التأخير النسبي | وحدة زمنية + قيمة الخصم | كل 15 دقيقة = خصم ربع يوم |
| خصم التأخير المباشر | مبلغ ثابت بالجنيه | كل تأخير = خصم 50 جنيه |
| خصم الغياب | قيمة يوم الغياب | يوم غياب = يوم راتب × 1.5 |
| خصم مخصص يدوي | يُضاف يدوياً من المدير | خصم جزاء أو مخالفة |

### ٦.٢ قواعد الإضافي

| نوع الإضافي | آلية التحديد | مثال |
|------------|-------------|------|
| إضافي ساعات عمل | قيمة الساعة الإضافية | ساعة إضافية = 1.5 × أجر الساعة |
| إضافي مخصص يدوي | مبلغ ثابت يُضاف يدوياً | بدل مواصلات — حافز أداء |

### ٦.٣ معادلة حساب الراتب

```
الراتب النهائي = الراتب الأساسي − إجمالي الخصومات + إجمالي الإضافي
```

> يُحسب تلقائياً في نهاية كل شهر بناءً على سجل الحضور والانصراف وكل الخصومات والإضافي المسجلة خلال الشهر.

## ٧. نظام الإجازات

### ٧.١ أنواع الإجازات الثلاثة

| النوع | الوصف | من يحددها |
|-------|-------|-----------|
| **إجازة ثابتة (متكررة)** | تُحدد مرة وتتكرر تلقائياً — مثال: كل خميس إجازة | Owner - HR |
| **إجازة مرة واحدة** | ليوم معين فقط — لا تتكرر | Owner - HR - Manager |
| **تحويل غياب لإجازة** | تحويل يوم الغياب لإجازة لإزالة الخصم | Owner - HR - Manager |

### ٧.٢ آلية تحويل الغياب لإجازة

```
الموظف يغيب يوم
       ↓
يُسجل غياب ويُحسب خصم تلقائياً
       ↓
المدير يفتح سجل الحضور ويختار اليوم
       ↓
يضغط "تحويل لإجازة" مع إدخال السبب
       ↓
الخصم يُزال تلقائياً من كشف الراتب ✅
```

## ٨. ملف الموظف

لكل موظف ملف شامل يضم كل بياناته ووثائقه وسجلاته في مكان واحد.

### ٨.١ محتويات الملف

| القسم | المحتوى |
|-------|---------|
| **البيانات الأساسية** | الاسم — الوظيفة — الفرع — الراتب — تاريخ التعيين — رقم الهاتف |
| **الأوراق الرسمية** | صور الأوراق المطلوبة التي يحددها الـ Owner (عقد — هوية — إلخ) |
| **سجل الحضور** | كل أيام الحضور والانصراف والتأخيرات منذ أول يوم |
| **سجل الإجازات** | رصيد الإجازات + تاريخ كل إجازة |
| **سجل الخصومات** | كل الخصومات مع الأسباب والتواريخ |
| **كشف الرواتب** | كشف راتب كل شهر محفوظ |
| **تقييمات الأداء** | تقييمات دورية من المدير |
| **التحذيرات والإنذارات** | سجل التحذيرات مع التاريخ والسبب (يشمل تغييرات الجهاز) |

### ٨.٢ صلاحيات الوصول للملف

| الدور | ما يراه |
|-------|---------|
| Owner | ملفات كل الموظفين في كل الفروع |
| HR | ملفات كل الموظفين في كل الفروع |
| Branch Manager | ملفات موظفي فرعه فقط |
| Viewer | مشاهدة فقط حسب النطاق المحدد |
| Employee | ملفه الشخصي فقط |

### ٨.٣ الأوراق المطلوبة

الـ Owner يحدد قائمة الأوراق المطلوبة من كل موظف. كل ورقة لها حالة:

- `مرفوعة ✅`
- `مطلوبة ⏳`
- `منتهية الصلاحية ❌`

## ٩. إدارة متعددة الفروع

### ٩.١ هيكل الفروع

لكل فرع:
- اسم وعنوان
- نطاق GPS محدد بالمتر
- QR Code خاص
- مديرين معينين
- موظفين تابعين له

### ٩.٢ رؤية الفروع حسب الدور

| الدور | الفروع التي يراها | الصلاحيات |
|-------|-------------------|-----------|
| Owner | كل الفروع | إدارة كاملة لكل الفروع |
| HR | كل الفروع | حسب الصلاحيات الممنوحة |
| Branch Manager | فرعه فقط | إدارة موظفي فرعه فقط |
| Employee | فرعه فقط | مشاهدة بياناته فقط |

### ٩.٣ Dashboard المقارنة (للـ Owner)

- نسبة الحضور في كل فرع
- إجمالي الرواتب لكل فرع
- معدل التأخير
- أعداد الموظفين
- مقارنة الأداء بين الفروع بشكل مرئي

## ١١. التقنيات المستخدمة

| الطبقة | التقنية | السبب |
|--------|---------|-------|
| Mobile Apps | Flutter (Dart) | cross-platform — iOS & Android من كود واحد |
| Backend API | PHP (Laravel) | قوي للـ SaaS — REST API |
| Database | MySQL | مناسب للـ multi-tenant |
| Hosting | VPS (DigitalOcean / Hetzner) | أفضل من Shared Hosting للـ SaaS |
| Authentication | Firebase Auth + Custom Tokens | Email/Password + Google + Apple + Tokens للموظفين |
| Face Recognition | Google ML Kit | يعمل على الجهاز — لا يرسل صور للسيرفر |
| Maps & GPS | Google Maps API | دقيق وموثوق |
| QR Code | mobile_scanner (Flutter) | سريع ودقيق |
| Secure Storage | flutter_secure_storage | تخزين Token الموظف على الجهاز بأمان |
| Push Notifications | Firebase FCM | مجاني وموثوق |
| الدفع | Paymob | الأنسب للسوق المصري |
| Storage (الأوراق) | AWS S3 أو Cloudflare R2 | تخزين آمن للملفات |
